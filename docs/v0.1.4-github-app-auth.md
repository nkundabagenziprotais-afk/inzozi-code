# V0.1.4 — GitHub App private repository access

## Goal

Allow Inzozi Code to clone private GitHub repositories without exposing personal access tokens to the browser, workspace URL, Git configuration, or audit logs.

## Trust boundary

1. The browser submits only a normal GitHub HTTPS repository URL.
2. The Inzozi Code API owns the GitHub App configuration and private key reference.
3. For repositories owned by `GITHUB_APP_OWNER`, the API mints a short-lived installation token.
4. The token is forwarded over the internal Docker network to the workspace runtime only for clone.
5. The workspace uses `GIT_ASKPASS`; the token is never placed in the repository URL.
6. The askpass script contains environment-variable references only and is deleted after clone.
7. Clone audit events record `authenticated: true/false`, never the token.

## GitHub App configuration

Create a GitHub App for Inzozi Code with the smallest initial permission set:

- Repository permissions → Contents: Read-only
- Metadata is available implicitly as required by GitHub Apps.
- No Issues, Pull Requests, Actions, Administration, Secrets, or organization write permissions are required for V0.1.4.

Install the app only on repositories Inzozi Code should be allowed to open. Prefer "Only select repositories" during the alpha.

Record:

- App ID
- Installation ID
- GitHub owner / organization name

Generate a GitHub App private key and store it only in the staging/production secret store. Never commit the `.pem` file.

## Runtime settings

Configure the API container with:

```text
GITHUB_APP_ID=<app id>
GITHUB_APP_OWNER=nkundabagenziprotais-afk
GITHUB_APP_DEFAULT_INSTALLATION_ID=<installation id>
GITHUB_APP_PRIVATE_KEY_PATH=/run/secrets/github-app-private-key.pem
```

Mount the private key read-only into the API container at deployment time. The workspace container must not receive this key.

## Repository behavior

For a repository such as:

```text
https://github.com/nkundabagenziprotais-afk/inzozi-code
```

Inzozi Code automatically selects the configured installation and mints a repository-scoped installation token.

For a public repository owned by another GitHub account, no GitHub App token is attached and anonymous HTTPS clone remains available.

## Security properties

- Personal access tokens are not required.
- The GitHub App private key stays in the API trust boundary.
- Installation tokens are short-lived.
- Tokens are scoped to the requested repository and `contents: read` for this milestone.
- Tokens are not embedded in clone URLs or Git config.
- The token is not returned to the browser.
- The token is not included in workspace audit records.
- `.pem` files and `secrets/` are ignored by Git.

## Staging verification

Before this milestone is approved:

1. Install the GitHub App on a private test repository.
2. Mount the private key into the API container only.
3. Confirm `/api/v1/workspaces/runtime` reports `github_app_configured: true`.
4. Open the private repository from Inzozi Code without entering credentials in the UI.
5. Confirm clone succeeds.
6. Inspect `.git/config` and verify the remote URL contains no token.
7. Inspect workspace `audit.jsonl` and verify no token appears.
8. Search container logs for the installation token and confirm it is absent.
9. Revoke the installation or remove repository access and confirm a new workspace clone fails safely.

## Follow-up

V0.1.4 covers repository read/clone. Git push, branch creation, commits, and pull requests will use separately scoped GitHub App permissions and explicit user actions in a later milestone.
