# Inzozi Code V0.1.12 — Draft pull request review UI

## Purpose

Expose the V0.1.11 draft pull request approval boundary inside Git Review without combining it with local commit, remote push, merge, or deployment.

## Visible workflow

1. Review working-tree diff.
2. Prepare and approve local commit.
3. Prepare and approve remote push.
4. Enter draft PR title, body, and allowed base branch.
5. Prepare draft PR.
6. Review exact head branch, base branch, commit and expiry.
7. Approve draft PR.
8. Open the resulting GitHub PR for review.

No merge control is shown.

## UI behavior

- Draft PR gate is visible below Remote Write in Git Review.
- Prepare is disabled until the exact commit approved in the UI has been successfully pushed in the current session.
- Backend remains authoritative and re-verifies the remote GitHub branch SHA.
- Allowed base branches use the backend alpha policy.
- PR title is limited to 120 characters.
- PR body is limited to 8000 characters.
- Approval card shows exact head → base and expiry.
- Successful result states that merge and deployment did not start.
- Existing matching PR can be returned instead of creating a duplicate.
- A resulting PR link opens GitHub in a new tab.

## Invalidation

File writes, branch creation, new local commits, new push preparation, Build and Debug activity clear stale downstream approval state. Backend approval expiry and SHA checks remain the final authority.

## Responsive review

Review at:

- 360 px
- 430 px
- 768 px
- 1280 px
- 1440 px
- 1920 px

At 360–430 px confirm:

- PR heading does not overflow.
- title/base/body fields stack cleanly.
- approval button remains full-width and readable.
- exact head/base relationship remains visible.
- Git diff remains scrollable.

## Safety copy

The UI must continue to communicate three distinct gates:

- Local commit
- Remote push
- Draft pull request

It must also state that merge remains disabled.

## Next milestone

Once staging is live and this flow is verified against a disposable repository, the next GitHub slice should read CI status and Aquila review results for the created PR. Merge must remain a later, separately approved action.
