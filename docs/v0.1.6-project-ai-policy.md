# Inzozi Code V0.1.6 — Project AI Roles

## Purpose

Give each project explicit non-secret AI routing preferences so users do not need to repeat provider names for ordinary work, while preserving per-task `@provider` overrides.

## Roles

The alpha policy contains:

- **Primary** — default provider for Ask, Plan, Build, Debug and Deploy-plan requests when no explicit provider is referenced.
- **Design** — default provider for the read-only Design mode.
- **Reviewer** — default provider for Review mode.
- **Maximum specialists** — caps how many referenced specialists Aquila may expose in a multi-provider run.

Default alpha policy:

```json
{
  "primary_provider": "aquila",
  "design_provider": "aquila",
  "review_provider": "chatgpt",
  "max_specialists": 2
}
```

## Precedence

Explicit provider references always win.

For example, if a project uses `@chatgpt` as reviewer but the user writes:

```text
@gemini review this migration
```

Inzozi Code routes to `@gemini`. If that connector is not active, it reports the connector as unavailable; it does not silently fall back to ChatGPT or Aquila.

## Design mode

V0.1.6 adds **Design** as a first-class Aquila mode. Design mode can search/read repository context and inspect Git status/diff, but it receives no write or command tools. This creates a review step between design thinking and Build implementation.

Intended flow:

```text
Design → human review → Build → tests → Git diff
```

When `@lovable` is eventually connected, a project can select it as Design provider without changing the agent API contract or IDE prompt grammar.

## Alpha persistence

Until authentication, organizations, tenant isolation, and the project database layer are implemented, project role preferences are stored in **browser local storage**, keyed by repository URL.

This alpha storage contains provider aliases only. It must never contain:

- API keys
- provider tokens
- GitHub installation tokens
- cPanel credentials
- SSH keys
- project secrets

The same policy is sent with each agent run and validated server-side. Later this schema will move to the authenticated project settings table without changing the UI contract.
