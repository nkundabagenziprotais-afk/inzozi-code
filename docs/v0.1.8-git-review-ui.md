# Inzozi Code V0.1.8 — Git Review UI

## Goal

Make the V0.1.7 commit approval boundary visible and understandable inside the Inzozi Code IDE.

The UI does not add remote Git write permissions. It exposes only safe local branch creation, review preparation and explicit local commit approval.

## User flow

1. Connect a repository to a guarded workspace.
2. Aquila or the user makes changes.
3. Open **Git Review** in the bottom panel.
4. If the workspace is on a protected branch, create a safe local branch using `feature/`, `fix/`, `ui/`, `hotfix/`, or `deploy/`.
5. Enter a one-line commit message.
6. Select **Prepare commit**.
7. Inzozi Code displays the exact reviewed diff, changed-path count, approval expiry and short Git tree hash.
8. Review the diff.
9. Select **Approve local commit**.
10. The API revalidates the working tree and exact Git tree hash before creating the local commit.
11. The interface reports the local commit SHA and explicitly states that nothing was pushed.

## Approval invalidation

The UI clears any existing approval when:

- the user saves a file;
- a guarded command is run;
- Aquila enters Build or Debug mode;
- the workspace is disconnected;
- a new safe branch is created.

The server remains authoritative: even if stale browser state exists, the API refuses approval when branch, HEAD, reviewed fingerprint, staged tree hash, approval expiry, or sensitive-path checks no longer match.

## UX rules

- The action is labelled **Approve local commit**, not generic "Approve".
- The footer says **push disabled**.
- Protected branches show a branch-creation form instead of a commit button.
- Exact diff remains visible in the review surface after Prepare.
- The approval card shows expiry and a shortened tree hash.
- Small screens use a scrollable review surface so the safety controls are not clipped.
- No credentials, tokens or secret values appear in this interface.

## Responsive review checklist

Review the complete flow at:

- 360 px: controls stack vertically; Approve local commit remains visible by scrolling the review panel.
- 430 px: branch/commit form remains usable without horizontal scrolling.
- 768 px: stacked application layout keeps Git Review readable.
- 1280 px: IDE, Aquila panel and bottom Git Review remain balanced.
- 1440 px: full desktop layout with readable diff.
- 1920 px: content does not stretch into oversized controls; diff remains the primary detailed review surface.

## Acceptance criteria

- TypeScript build succeeds.
- Existing API/workspace security tests remain green.
- Git Review loads the actual current branch/status/diff from the workspace API.
- Protected branches cannot expose Prepare commit.
- Prepare commit displays the server-issued review lock.
- Approval changes create a local commit only.
- No Push, PR, Deploy, or production action is introduced in the UI.

## Next milestone
