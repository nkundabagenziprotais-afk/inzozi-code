# Inzozi Code v0.1.13 — Alpha workspace polish

This milestone refines the first private staging workspace without changing the existing guarded repository, Aquila, or Git approval architecture.

## Product goals

- make the first-run state useful instead of visually empty;
- improve hierarchy between Explorer, editor, Aquila, and the bottom command/review panel;
- make Aquila modes explain their safety contract before a run;
- keep provider references available without giving them permanent visual priority;
- reduce the default terminal footprint while keeping command output and Git Review one click away;
- prepare the repository connection experience for an account-based GitHub App selector while retaining the manual HTTPS alpha flow;
- improve responsive behavior across the required review sizes.

## UI changes

### First-run workspace

The editor now presents a focused Inzozi Code onboarding surface with two real actions: connect a repository or move directly to the Aquila composer. The trust strip communicates the actual current safety boundaries: guarded tools, human approval for commit/push/draft PR, and merge disabled.

The Explorer keeps the manual HTTPS repository flow for the private alpha, but introduces the future GitHub repository-picker shape without pretending the GitHub App is already active.

### Aquila

Aquila is organized into three clearer layers:

1. mode and mode contract;
2. optional provider references and project AI role configuration;
3. agent output/context and the prompt composer.

Provider references are collapsed by default. Explicit `@mentions` remain available and focus returns to the prompt after selecting a reference.

### Bottom panel

The terminal/Git area starts collapsed. Selecting Terminal, Git Status, Git Diff, Git Review, or running an approved command expands it. The user can collapse it again without losing the selected tab or output.

### Connected repository empty state

After a workspace connects, the editor empty state now offers direct actions to plan with Aquila or inspect Git status instead of displaying only explanatory text.

## Responsive review checklist

Review each size with both no repository connected and a connected workspace:

- **360 px** — single-column mobile review mode; primary actions remain reachable; command shortcuts collapse; Aquila composer remains usable.
- **430 px** — single-column mobile review mode; mode controls wrap cleanly; onboarding actions stack.
- **768 px** — Explorer, editor, and Aquila stack vertically with preserved working areas.
- **1280 px** — three-pane workspace remains usable without overlapping controls; onboarding trust items stack when needed.
- **1440 px** — standard three-pane development layout.
- **1920 px** — expanded Explorer/editor/Aquila proportions without excessive empty chrome.

## Safety boundaries unchanged

This milestone does not enable GitHub App credentials, OpenAI credentials, merge, auto-merge, production deployment, or public staging access. Existing commit, push, and draft pull-request approval gates remain unchanged.

## Preview

Use the private staging deployment and SSH tunnel. After deploying this branch, review through `http://127.0.0.1:8080` and keep `code-staging.inzozidigital.com` unpublished until authentication and workspace isolation are ready for broader exposure.
