# V0.1.1 — Workspace runtime

## Goal

Prove that Inzozi Code can work against a real Git repository without giving Aquila unrestricted host-shell access.

## Flow

1. Inzozi Code API requests a workspace.
2. Workspace runtime validates a GitHub HTTPS URL and clones the repository.
3. File APIs expose only paths inside the repository boundary.
4. Writes use optional SHA-256 optimistic locking to avoid clobbering concurrent edits.
5. Build/test commands are selected from predefined recipes rather than arbitrary shell strings.
6. Git status and diff are generated from the real working tree.
7. Mutations and command runs are written to the workspace audit log.

## Review criteria

- Directory traversal attempts are rejected.
- Arbitrary command strings cannot be executed.
- `.git` cannot be overwritten through the file API.
- Git diff reflects file writes.
- A failed private clone does not prompt for credentials or leak secrets.
- Removing a workspace deletes its temporary repository data.

## Deferred intentionally

- GitHub App installation tokens for private repositories.
- Per-session Docker/VM creation.
- Network egress allowlists.
- Workspace checkpoints/restore.
- Git commit/push/PR operations.
- Live Aquila model access.
