# Inzozi Code V0.1.5 — Aquila Provider Routing

## Goal

Allow a project user to reference an AI model or external specialist with `@name` while Aquila remains the default engineering orchestrator and the guarded workspace remains the only repository execution boundary.

Examples:

```text
@chatgpt review the API architecture
@chatgpt @claude compare security concerns
@lovable propose a cleaner dashboard direction
@cursor review this implementation
```

## Routing semantics

- No provider mention → `@aquila` is primary.
- One recognized provider mention → that provider becomes primary when its connector is active.
- Multiple recognized provider mentions → Aquila stays primary and the other references become specialists.
- Unknown `@mentions` never silently become providers.
- A registered but unavailable provider is reported as unavailable. Inzozi Code never impersonates it and never substitutes another provider silently.

## Aquila manager pattern

When multiple providers are referenced, Aquila remains responsible for the final project response and tool policy. A configured specialist can be exposed to Aquila as a bounded tool. The specialist receives only the task/evidence passed to it by Aquila and does not receive host or production control.

In V0.1.5, `@chatgpt` can be used either directly or as a bounded second-opinion specialist when referenced alongside another provider/Aquila. Additional providers will implement the same registry contract rather than adding provider-specific logic to the UI.

## Guarded workspace policy

Agent repository tools are selected by mode:

### Ask / Plan / Review / Deploy

Read-only tools only:

- repository text search
- file read
- Git status
- Git diff

`Deploy` is plan/review only in this milestone. It has no deployment execution tool.

### Build / Debug

Adds:

- automatic preflight working-tree checkpoint
- guarded file write with SHA-256 optimistic locking
- named build/test recipes only

Allowed named recipes are currently:

- `python_compile`
- `python_tests`
- `node_build`
- `node_test`
- `node_lint`
- `php_tests`
- `composer_validate`

There is still no arbitrary shell-string endpoint.

## Secret boundary

The OpenAI key must exist only as a server-side process/container secret named `OPENAI_API_KEY`.

- It is intentionally omitted from `.env.example`.
- It is not sent by the browser.
- It is not stored in application settings or provider registry payloads.
- It is not committed to GitHub.
- CI does not require a live key; provider and tool-policy tests are offline.
- Agents SDK tracing is configured with sensitive input/output capture disabled for the run.

The secure key created for Inzozi Code still needs to be injected into the staging API runtime when the staging server exists. Creating a Platform key does not automatically put it inside a future VPS container.

## UI behavior

The Aquila panel exposes a compact `REFERENCE` row. Provider chips show:

- filled indicator: implemented and configured in the current runtime
- hollow indicator: registered but not configured/implemented

Selecting a chip inserts the mention into the current prompt rather than switching a global hidden setting. This keeps model routing explicit and reviewable per task.

## Acceptance checks

1. `@OpenAI` normalizes to `@chatgpt`.
2. Email addresses are not treated as provider mentions.
3. One recognized mention selects that provider.
4. Multiple recognized mentions retain Aquila as manager.
5. Unknown mentions do not alter provider routing.
6. Unavailable providers are reported instead of impersonated.
7. Ask/Plan/Review/Deploy expose no file-write or command tools.
8. Build/Debug create a checkpoint before agent edits when a workspace is connected.
9. Build/Debug have no arbitrary shell tool.
10. Agent responses return the resulting Git diff for human review.
11. The UI remains reviewable at 360, 430, 768, 1280, 1440 and 1920 px before merge.

## Next provider adapters

### Lovable

Use Lovable's MCP/OAuth surface as a design/prototyping specialist. Aquila should send bounded UI context and receive design/project evidence back; Lovable should not receive cPanel or production credentials.

### Cursor

Use Cursor's Agent Client Protocol (ACP) surface through a server-side adapter. The connector should expose explicit permissions and scoped project context rather than embedding Cursor credentials in the browser.

### Claude / Gemini

Add provider adapters behind the same registry interface. Per-project credentials must be stored as encrypted server-side secrets, and project/organization policy decides which providers are allowed.

### Local / self-hosted

Add an OpenAI-compatible base URL/model adapter for self-hosted models. This becomes the path toward greater model independence without changing the Aquila UI or workspace policy.
