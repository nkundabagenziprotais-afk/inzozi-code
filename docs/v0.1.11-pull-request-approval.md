# Inzozi Code V0.1.11 — Pull request approval gate

## Purpose

This slice adds the next controlled GitHub action after an approved remote push: creation of a **draft pull request**.

It does not add merge, auto-merge, production deployment, cPanel deployment, reviewer assignment, or branch deletion.

## Trust boundary

Pull request creation is deliberately separate from both local commit approval and remote push approval.

Flow:

1. Working tree must be clean.
2. Current branch must match the Inzozi Code safe branch convention: `feature/`, `fix/`, `ui/`, `hotfix/`, or `deploy/`.
3. User provides PR title, optional body, and an allowed base branch.
4. Prepare captures the exact local branch and HEAD commit.
5. The approval expires after 10 minutes.
6. Approve rechecks the local clean branch and exact HEAD.
7. Only after approval does the API mint a repository-scoped GitHub App token with:
   - `Contents: read`
   - `Pull requests: write`
8. Inzozi Code reads the remote branch ref and requires GitHub to point to the exact reviewed commit SHA.
9. Inzozi Code checks whether an open PR already exists for the same head/base pair.
10. If none exists, it creates a **draft** pull request with maintainer modifications disabled.
11. The response reports `merged: false` and `deployment_started: false`.

## Allowed base branches in alpha

- `main`
- `master`
- `develop`
- `development`
- `staging`

This keeps the first milestone predictable. Broader branch policy should move into project/org configuration when persistent project settings and RBAC are introduced.

## Idempotency

If an open PR already exists for the exact repository, head branch, and base branch, the integration returns that PR instead of opening another one.

## Security

- PR token is minted only after explicit approval.
- Token is not returned to the browser.
- Token is not stored in Git configuration, workspace metadata, repository URLs, or audit records.
- PR creation receives no `Contents: write` permission.
- Remote branch SHA must match the reviewed local commit.
- Pull requests are draft by default.
- `maintainer_can_modify` is false in alpha.
- No merge or auto-merge endpoint is exposed by this slice.

## GitHub App requirement

For repositories where Inzozi Code should create PRs, configure the GitHub App with:

- Contents: Read and write (needed by the separate push capability)
- Pull requests: Read and write (needed by this slice)

At runtime, the installation token is still narrowed per action: push requests Contents write only; PR creation requests Contents read + Pull requests write.

## Acceptance tests

- Prepare rejects dirty worktrees.
- Prepare rejects unsafe head branches.
- Prepare rejects unsupported base branches.
- Prepare binds title/body/base/head branch/commit to one approval ID.
- Approve rejects changed local HEAD/branch/worktree.
- Approve requests Contents read + Pull requests write only.
- Approve verifies remote branch SHA equals the approved local SHA.
- Remote SHA mismatch blocks PR creation.
- Existing matching open PR is reused.
- New PR is always draft.
- No merge or deployment is started.
