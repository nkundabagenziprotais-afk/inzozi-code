# Inzozi Code V0.1.3 — Search and Checkpoints

## Goal

Add the repository-context and recovery primitives Aquila needs before autonomous multi-file edits.

## Repository search

`GET /api/v1/workspaces/{workspace_id}/search?q=...`

The runtime performs bounded, case-insensitive UTF-8 text search and returns file path, line number and a short excerpt.

Search deliberately skips generated/heavy directories including:

- `.git`
- `node_modules`
- `.venv` / `venv`
- `vendor`
- `dist` / `build`
- `.next` / `.nuxt`
- `coverage`

Files above the configured per-file search limit and binary files are ignored.

## Working-tree checkpoints

Checkpoint endpoints snapshot the repository working tree outside `.git`.

- `POST /api/v1/workspaces/{workspace_id}/checkpoints`
- `GET /api/v1/workspaces/{workspace_id}/checkpoints`
- `POST /api/v1/workspaces/{workspace_id}/checkpoints/{checkpoint_id}/restore`
- `DELETE /api/v1/workspaces/{workspace_id}/checkpoints/{checkpoint_id}`

A checkpoint preserves tracked and untracked working files while intentionally excluding Git metadata. Restore replaces working-tree content but leaves `.git` intact, so branch/history identity is preserved and Git can report the restored state normally.

## Safety limits

- Checkpoint size is bounded; default maximum is 100 MiB per working-tree snapshot.
- At most 20 checkpoint metadata records are returned by the listing endpoint.
- Symlinks are preserved rather than followed during snapshot/restore.
- Search result counts and excerpts are bounded.
- Checkpoint creation/restore/delete actions are written to the workspace audit log.

## Why this precedes live Aquila

Before the model receives editing tools, Inzozi Code must be able to find relevant code without dumping entire repositories into context and recover from a bad multi-file edit without rewriting Git history. These primitives become deterministic tools for the future agent orchestration layer.
