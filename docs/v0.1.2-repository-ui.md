# Inzozi Code V0.1.2 — Repository UI

## Goal

Turn the V0.1 shell into a real repository workspace interface backed by the guarded workspace runtime.

## Implemented flow

1. Enter a GitHub HTTPS repository URL and optional ref.
2. Create a guarded workspace.
3. Browse the real repository directory tree.
4. Open UTF-8 source files.
5. Edit source files in Monaco Editor.
6. Save with SHA-256 optimistic locking.
7. Refresh real Git status and Git diff.
8. Run predefined build/test recipes and display their output.
9. Destroy the workspace when disconnected.

## Safety boundary

- Browser never receives host filesystem access.
- Browser never receives Docker socket access.
- File writes use the workspace API, not host mounts.
- The UI exposes named command recipes only; there is no arbitrary shell command field.
- Git metadata remains protected by the workspace runtime.
- cPanel and production credentials are not part of this milestone.
- Aquila remains on the mock provider until the workspace loop is reviewed.

## Known limitation

V0.1.2 can clone public GitHub HTTPS repositories. Private repositories require the planned GitHub App installation-token flow; credentials must not be embedded into repository URLs or persisted in the browser.

## Review checklist

Functional:
- Connect a public repository.
- Navigate into and out of directories.
- Open a text source file.
- Edit and save the file.
- Confirm Git status changes.
- Confirm Git diff displays the edit.
- Run at least one recipe appropriate to the repository.
- Disconnect and confirm the workspace is destroyed.

Responsive review:
- 360px small mobile
- 430px mobile
- 768px tablet
- 1280px laptop
- 1440px desktop
- 1920px wide screen
